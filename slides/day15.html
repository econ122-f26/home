1. Growing a tree

What makes a good question?

A class of 100 students; half (50) are data science majors. You want to guess which ones. You get one yes/no question. What would you ask?

(1) “Have you taken a programming class?”    (2) “Born in January–June?”

Question Answer Students Data science majors Share majors
Taken a programming class? Yes 50 45 90%
No 50 5 10%
Birthday in January-June? Yes 50 25 50%
No 50 25 50%
  • Good: each group is mostly one kind (“No” → almost surely not a major).
  • Bad: both groups look like the whole class (50%). Next: a number for “mixed.”

Measuring impurity: the Gini index

Impurity = how mixed a group is. Trees use the Gini index: \(\;G = 2p(1 - p)\), where \(p\) = share in one class (here: majors).

Group Share majors, p Gini, G
All majors, or no majors (pure) 1.00 or 0.00 0.00
Half and half, like the whole class (most mixed) 0.50 0.50
  • A question’s score: its two groups’ \(G\), averaged by group size. Lower is better.
    • Programming class: (50 × 0.18 + 50 × 0.18) / 100 = 0.18.
    • Birthday: (50 × 0.50 + 50 × 0.50) / 100 = 0.50, the same as not asking.

How does it pick the first question?

Back to student debt. Score every cutoff on every predictor: which question wins?

  • Each point is one question (“income < 50?”, “income < 51?”, …), scored the same way. Dashed: before any split (0.42). Dot: each predictor’s best.
  • The winner: income at 151.5. Above it, almost nobody has heavy debt. Unrelated columns stay on the dashed line.

Then repeat inside each box

  • Recursive binary splitting (ISL 8.1):
    • Split the data in two with the best question.
    • Do the same inside each half, and inside each half of those, …
    • Here: among income < 151.5, the best question is about sat (merit aid), then income again.
  • Greedy: each split is the best one right now. It never looks ahead.
  • When to stop? rpart’s defaults stop when a box is small (under 20 students) or a split barely helps. Here: 6 leaves.
tree <- rpart(heavy_debt ~ ., data = students, method = "class")   # rpart package
rpart.plot(tree, type = 4)                                         # rpart.plot package

2. How flexible is a tree?

Grow it all the way

No stopping rule: split until every leaf is pure. Is that a better tree?

  • 282 leaves. Training error 0.0%, but CV error 23.8% (vs 18.1% for the 6-leaf tree). It boxed in every exception, like KNN with \(K = 1\).

Trees: strengths and weaknesses

Strengths Weaknesses
Easy to explain: a flowchart Diagonal or smooth boundaries take many boxes
Cutoffs and “and” rules come naturally Often less accurate than other methods
Ignores predictors that don’t help Unstable: new data can change the whole tree
No standardizing: a cutoff doesn’t care about units Too many leaves overfit, like K = 1
  • If aid phased out along a diagonal (a points formula of income and SAT), the tree would need a staircase. The activity: the colleges, where the boundary is closer to a line.

Summary

A decision tree predicts with a sequence of yes/no questions about the predictors.

  • Each split cuts one predictor at a cutoff; the leaves are rectangles in predictor space.
  • Classification: predict a leaf’s majority class; splits minimize the Gini index.
  • Regression: predict a leaf’s mean; splits minimize the RSS.
  • Grown top-down and greedily, one best split at a time.
  • Wins when the truth is a few cutoffs and some predictors don’t matter (the debt squeeze).
  • Flexibility = number of leaves. Grown until pure, training error is 0%.

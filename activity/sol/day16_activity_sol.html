Part 1: Grow Big, Then Cut Back

Task 1.1: The pruning helper

# Prune `tree` to the largest tree in its pruning sequence with at most
# `leaves` leaves
prune_to <- function(tree, leaves) {
  steps <- tree$cptable                          # one row per pruned tree
  row <- max(which(steps[, "nsplit"] + 1 <= leaves))
  prune(tree, cp = steps[row, "CP"])
}

Task 1.2: Cut it back

set.seed(1)   # rpart runs its own CV while it grows the tree (Part 2)
full_tree <- rpart(Private ~ tuition + undergrad, data = College,
                   method = "class", control = no_stopping)
rpart.plot(full_tree, type = 4)   # the full tree, grown until every leaf is pure

tree6 <- prune_to(full_tree, 6)
rpart.plot(tree6, type = 4, extra = 106)

No: the full tree has 66 leaves, and most of its bottom splits isolate a handful of colleges; nobody could explain it, and its labels don’t even fit on the page. The 6-leaf tree fits in a sentence.

The full tree always wins on training error (here 0.0% vs 6.6% for 6 leaves), because every extra split can only fit the training colleges better, noise included. So training error would always pick the biggest tree, which Day 15 showed is not the best on new colleges. To choose a size we need error on colleges the tree didn’t see: CV.

# 2. From nsplit = 5 to nsplit = 7: rel error saved per split added
row5 <- cp_table %>% filter(nsplit == 5)

(row5$`rel error` - row7$`rel error`) / (row7$nsplit - row5$nsplit)
## [1] 0.01650943
row5$CP
## [1] 0.01650943
# 4. Where the default cp = 0.01 stops: the last row whose CP is at least 0.01
default_row <- cp_table %>% filter(CP >= 0.01) %>% slice_tail(n = 1)
default_row$nsplit + 1
## [1] 8
  1. nsplit = 2 means 3 leaves. Its training error rate is 0.297 × 27.3% = 8.1%.
  2. Going from 6 to 8 leaves adds 2 splits, and rel error drops from 0.241 to 0.208: 0.017 per split, the same as the CP in the nsplit = 5 row (0.017). So a row’s CP is how much (relative) training error each split in the next step saves: the “price” those splits are worth.
  3. No. xerror falls to 0.283 at 12 leaves, then rises again, to 0.368 for the full tree.
  4. cp = 0.01 keeps every step whose CP is at least 0.01, so it stops at 8 leaves (CP = 0.012; the next step’s CP is below 0.01).

In words: CP is the training error a step’s splits save, per split, as a share of the root error. rel error is the tree’s training error as a share of the root error. xerror is the same thing measured by CV, on colleges each tree didn’t see. Training error can only fall as the tree grows, because every split fits the training colleges better. CV error falls while the splits find real patterns and rises once they start fitting noise (Day 9’s U-shape).

The tree’s case is that anyone can follow it, as we just did for the Claremont Colleges: if the website needs to show its reasoning, a 10-leaf tree is easy to display.

Bonus

Bonus 1: Your own CV

sizes <- c(1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48)
errors <- matrix(NA, nrow = length(sizes), ncol = 5)

for (f in 1:5) {
  train <- College %>% filter(fold != f)
  test  <- College %>% filter(fold == f)
  big <- rpart(Private ~ tuition + undergrad, data = train,
               method = "class", control = no_stopping)
  for (i in 1:length(sizes)) {
    pruned <- prune_to(big, sizes[i])
    pred <- predict(pruned, test, type = "class")
    errors[i, f] <- mean(pred != test$Private)
  }
}

cv_results <- tibble(size = sizes,
                     cv_error = rowMeans(errors),       # mean of each row
                     se = apply(errors, 1, sd) / sqrt(5))   # SE of each row's mean

Why a new tree in each fold: full_tree was grown on all 777 colleges, including the ones in the test fold. Pruning it and testing on fold f would score the tree on colleges it already saw, the same mistake as scoring by training error. Growing the tree and pruning it have to happen on the training folds only. (rpart does the same thing inside printcp’s xerror.)

The loop’s lowest CV error is at 12 leaves (7.8%), and the one-SE rule picks 6 leaves (8.1%). printcp() picked 10 (8.1%). Close: the curve has a wide, flat bottom, so different folds settle on nearby sizes with about the same error.

Bonus 2: Did pruning beat the default?

errors_default <- rep(NA, 5)
for (f in 1:5) {
  train <- College %>% filter(fold != f)
  test  <- College %>% filter(fold == f)
  default_tree <- rpart(Private ~ tuition + undergrad, data = train, method = "class")
  pred <- predict(default_tree, test, type = "class")
  errors_default[f] <- mean(pred != test$Private)
}
mean(errors_default)
## [1] 0.08233251

On Day 14’s folds the default tree scores 8.2% and the one-SE tree from Bonus 1 scores 8.1%: essentially a tie. In Part 2, cp = 0.01 stopped at 8 leaves, right next to the one-SE size, inside the flat bottom of the CV curve. So for these colleges the default’s price per split happens to land on a good size. On the flood map, the small basins each saved less than 1% of the root error, so the default stopped well before the bottom of the curve. The default is a fixed guess; CV checks it on your data.

Bonus 3: Another CV seed

seeds_tab <- tibble()
for (s in c(1, 2, 3, 4, 5)) {
  set.seed(s)
  t <- rpart(Private ~ tuition + undergrad, data = College,
             method = "class", control = no_stopping)
  tab <- as_tibble(t$cptable)
  b <- tab %>% slice_min(xerror, n = 1, with_ties = FALSE)
  o <- tab %>% filter(xerror <= b$xerror + b$xstd) %>% slice_min(nsplit, n = 1)
  seeds_tab <- bind_rows(seeds_tab, tibble(seed = s, lowest = b$nsplit + 1, one_se = o$nsplit + 1))
}
seeds_tab

The tree itself never changes (the seed only changes rpart’s CV folds), but the size with the lowest xerror moves (from 10 to 27 leaves) because the bottom of the curve is flat. The one-SE size moves less (6 to 10 leaves) and is never bigger. It’s the rule to trust: it doesn’t pretend to choose between sizes that CV can’t tell apart.

Bonus 4: Many trees

errors_bag <- rep(NA, 5)
set.seed(16)
for (f in 1:5) {
  train <- College %>% filter(fold != f)
  test  <- College %>% filter(fold == f)
  votes <- matrix(NA, nrow = nrow(test), ncol = 100)
  for (b in 1:100) {
    boot <- train %>% slice(sample(nrow(train), replace = TRUE))   # bootstrap sample
    big <- rpart(Private ~ tuition + undergrad, data = boot,
                 method = "class", control = no_stopping)
    votes[, b] <- predict(big, test, type = "class") == "Yes"
  }
  pred <- if_else(rowMeans(votes) > 0.5, "Yes", "No")
  errors_bag[f] <- mean(pred != test$Private)
}
mean(errors_bag)
## [1] 0.07076923
sd(errors_bag) / sqrt(5)
## [1] 0.004912803

The vote scores 7.1% (SE 0.5%), better than the pruned tree (8.1% on the same folds) and about the same as logistic regression (6.8%). Each full tree overfits in its own way, because each saw a different bootstrap sample. Their mistakes on a given college don’t all go the same way, so the majority vote cancels much of the noise (lower variance) while keeping the trees’ flexibility (low bias). This is bagging, Day 17’s topic.
